* The house style

~phase_1/~ is worth imitating, because the form it settled on did real work. It
proceeds scenario by scenario. Each states the problem with a concrete example,
lists the options that were considered — including the ones a reasonable person
would reach for first — marks the one selected, gives the rationale, and then
records the known limitation of having chosen it. A status table at the front
says which scenarios are decided.

Two things that form bought, and that are worth carrying into Phase 3:

- *Rejected options stay on the page.* Half the document's value is that the
  obvious alternative is written down together with why it lost, so it does not
  get re-proposed every few weeks.
- *Every decision names what it costs.* No decision is recorded as free. The
  "known limitation" paragraph is what makes it possible to revisit one later
  without reconstructing the argument from scratch.

There is also a single property that most of Phase 1's decisions turn out to be
defending — that the schema is a function of document structure, not of data
values. Finding the equivalent invariant for Phase 3 is probably the first real
task there.
