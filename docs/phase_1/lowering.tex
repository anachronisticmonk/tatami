\section{Purpose and scope}

This document fixes the meaning of Phase~1: the translation from JSON input to
a set of generated OCaml modules. It does not cover the Phase~2 effect
lowering.

The design note already fixes the relational-to-OCaml half of the
translation: table becomes module, row becomes a value of type \texttt{t},
column becomes a record field, primary key becomes an abstract \texttt{id},
foreign key becomes a field holding another module's \texttt{id}, joining on
it becomes an accessor function, and a nullable column becomes an
\texttt{option} field. Nothing in that correspondence is open.

What this document settles is the other half --- JSON to relational --- and
the shape of the module surface that results. Each scenario below states the
options that were considered, with an example of each, and then records which
one was selected.

\paragraph{Delivery.} The tool is intended to be used through a web
interface: JSON is supplied directly, and the generated modules are presented
in an editor-like view. Two consequences bear on the decisions below. Any
configuration a decision depends on --- the path marking of S9, for instance
--- must be a persisted, exportable input rather than interface state, so that
the same input regenerates the same modules outside the interface. And the
generated modules are read by people in an editor rather than consumed as a
build artifact, which raises the weight of the naming decisions deferred to
S22. An interface that invites a single pasted document will also routinely
produce the weaker schema described in S0.

\paragraph{The unit of inference is the path, across all documents.}
Throughout, a scenario describes \emph{the set of values observed at a path
across the whole input}, not the value at a path in one document. A path is a
position in the schema, written \texttt{.price} or \texttt{.items[].qty}.
Several scenarios are invisible at single-document granularity: a field that
is an integer in one document and a string in another, or an array that
happens to be empty everywhere.
