\subsection*{S9. Map-shaped object (keys are data)}

Two inputs that are structurally identical and semantically unrelated:

\begin{lstlisting}[style=json]
{ "point": { "x": 1, "y": 2 } }

{ "users": { "u_1001": { "name": "ada" },
             "u_1002": { "name": "grace" } } }
\end{lstlisting}

Both are objects whose members are values. But \texttt{x} and \texttt{y} are
\emph{schema}, repeated in every document, while \texttt{u\_1001} is
\emph{data}, and the next document carries entirely different keys. Nothing in
the JSON distinguishes them.

\paragraph{Why this decides more than it appears to.}
The property worth protecting is that \textbf{the schema is a function of
document structure, not of data values.} Treating a map as a record violates
it: the generated record's fields become the identifiers that happened to
appear in the sample, so a document arriving later with a new key has no
column to go in.

\begin{lstlisting}[style=json]
inference corpus:  { "users": { "u_1001": {...}, "u_1002": {...} } }
                   -> record with fields u_1001, u_1002

later document:    { "users": { "u_1003": {...} } }
                   -> no such column; shredding is undefined here
\end{lstlisting}

For a statement quantified over the exact corpus that was used for inference,
this is harmless. For the statement that matters --- schema fixed once,
documents arriving afterwards --- shredding must be total on everything the
schema accepts, and here it is not: a new key is a schema change and a
recompilation rather than a new row.

\options
\begin{enumerate}[label=\textbf{(\alph*)}]
  \item \textbf{No detection.} Every object is a record. Deterministic, but
        makes the schema depend on data values, as above.
  \item \textbf{Heuristic detection}, lowering automatically as a map on
        signals such as key-set variability, key count, and uniformity of the
        values. Makes the schema a function of the sample: adding a document
        can flip a path between record and map.
  \item \textbf{Explicit, path-directed marking.} Every object is a record
        unless its path is marked as a map. \selected
  \item \textbf{Heuristic detection that rejects} rather than guesses,
        directing the user to mark the path.
\end{enumerate}

\decision{Explicit, path-directed marking. Inference takes the marking as an
additional input, so the signature becomes
$\mathit{Corpus} \times \mathit{Annotation} \rightarrow \mathit{Schema}$ ---
still deterministic, still total, and still a function of structure once the
marking is given.}

A marked path lowers to the same table an array of objects produces, with the
ordering index replaced by a string key. The parent gains no column; the child
carries the parent reference and the key, and since the record is the row
(S21) both appear as fields:

\begin{lstlisting}[style=ml]
module User : sig
  type id
  type t = { id : id; root_id : Root.id; key : string; name : string }
  val get : db -> id -> t
end

module Root : sig
  type id
  type t = { id : id }
  val get : db -> id -> t
  val users : db -> t -> User.t list
end
\end{lstlisting}

\paragraph{Surface form.} The marking is written as a configuration file
listing paths:

\begin{lstlisting}[style=json]
maps = [".users", ".index.by_id"]
\end{lstlisting}

This is the form the web interface exports, so the same file drives generation
both inside and outside the interface and a generated result can be reproduced
without it. An inline annotation or an interface toggle would be
interchangeable --- each identifies \emph{paths} --- but the file is the
single form of record.

A configuration option that names a \emph{threshold} --- treat any object with
more than $N$ members as a map --- is not an equivalent spelling and is
excluded. It is deterministic given $N$, but it remains a function of data
values: member counts grow with the corpus, so adding documents can carry a
path across the threshold and change the schema. Only path-directed marking
preserves the structural property above.

\rationale{This keeps shredding total on documents that arrive after the
schema is fixed --- a new key is a new row, not a new column --- and it keeps
the eventual equivalence statement free of any need to quantify over an
unspecified heuristic. Formally the marking is an input, not a guess.}

\limitation{Determinism is not protection. An unmarked map still lowers as a
record and still produces a module with one field per key. A detection
heuristic may be added later as a usability aid, but it must remain advisory:
it may surface a suggestion for a person to accept, and must never change what
is generated on its own.}
