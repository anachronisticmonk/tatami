What “proved” means here

Every claim in this document is a theorem in the repository, accepted by Lean's type checker. Nothing is asserted in prose and taken on trust.

No open goals

Lean records an unfinished proof as sorry and warns on every one. The build reports none. This is mechanical, not a claim about our diligence: lake build prints a warning for each, and there are no warnings to print.

No extra axioms

#print axioms pipeline_correct reports propext, Classical.choice and Quot.sound — the three Lean itself is built on. In particular not sorryAx, which is what an unfinished proof would leave behind even if the warning were suppressed.

Mathlib is not used. Everything below rests on Lean's own library, which means the lemmas about lists, orders and sorting that the proofs need were either found in core or proved here.

02

The guarantee

For a corpus inference accepted and a schema the generator accepted, five things hold of the output. This is one theorem, pipeline_correct; everything else in this document is what it rests on.

#GuaranteeGroups
1Well-formedness. The emitted signature repeats no module name, no value name within a module, and no field name within a record. That is what “a legal OCaml signature” amounts to for this fragment.
Without it the generator could emit two record fields of one name, which OCaml rejects outright.
gen_wellFormed
2Canonicity. The schema is determined by the corpus as a collection of documents, not by the order they arrived in. Shuffle the corpus and the answer is equal, not merely equivalent.
Without it two runs over the same data could disagree, and the output would depend on the order files happened to be read in.
infer_perm
3Structure preservation. The tree the documents induce and the graph a reader finds in the generated signatures are the same graph — every edge one has the other has, distinct tables get distinct modules, and every table is reachable from the root.
Each clause earns its place. Without the first two an edge could be lost; without the next two one could be invented; without injectivity two tables could collapse into one module and the agreement would be vacuous; without rootedness a table could be declared and never reached, which is a table the loader creates and never fills.
gen_tree_complete gen_tree_sound gen_moduleName_injOn gen_rooted
4Principality. Each member is given the principal type of the values seen there: one that admits every one of them (adequacy), and the least type that does (minimality).
Adequacy alone is nearly free — a corpus of integers is adequately described by float, or by int option. Minimality rules the loose answers out, and the two together pin the type from both sides.
infer_admits infer_least
5Nullability. A column is optional exactly when some document lacked a value there. Two halves: every visit to a table is accounted for at each member — a value, an explicit null, or an absence — and the option flag is set precisely when the member carried a value in fewer than all of them.
Absence is computed by truncating subtraction. Without the counts identity a member some document had omitted could report zero absences, come out non-optional, and the generator would emit string where the data needs string option. That output compiles and then fails on the first document missing the member, with nothing to say what went wrong.
infer_counts

What it does not say. Every part is conditional on both stages returning ok. Both refuse inputs — a member holding two types with no common type, a schema whose tree a signature cannot express — and the guarantee is about what is emitted, not about what is accepted. It also says nothing about rows: the program emits a description of tables, and the loader that fills them is OCaml, outside what Lean sees here.

nullability_sound

A column is optional exactly when some document lacked a value there -- neither a missing `option` nor a gratuitous one.

theorem nullability_sound (cfg : Config) (ds : List Doc) (ts : Tables)
    (hinf : inferCorpus cfg ds = .ok ts) :
    ∀ p t, (p, t) ∈ ts → ∀ k o, (k, o) ∈ t.members →
      o.values + o.nulls + o.absent = t.visits
      ∧ (o.nullable = true ↔ o.values < t.visits)

pipeline_correct

Everything below in one statement: for a corpus inference accepted and a schema the generator accepted, the signature is well formed, the schema is canonical, the structure is preserved and the types are principal.

theorem pipeline_correct (cfg : Config) (nm : Naming) (ds : List Doc)
    (ts : Tables) (f : File)
    (hinf : inferCorpus cfg ds = .ok ts)
    (hgen : gen nm (toSchema ts) = .ok f) :
    f.WellFormed
  ∧ (∀ es ts', ds.Perm es → inferCorpus cfg es = .ok ts' → ts = ts')
  ∧ ((∀ p q, CollEdge (toSchema ts) p q →
        FileCollEdge f (moduleName nm p) (moduleName nm q))
     ∧ (∀ p q, RefEdge (toSchema ts) p q →
        FileRefEdge f (moduleName nm p) (moduleName nm q))
     ∧ (∀ t u, t ∈ toSchema ts → u ∈ toSchema ts →
          FileCollEdge f (moduleName nm t.path) (moduleName nm u.path) →
          CollEdge (toSchema ts) t.path u.path)
     ∧ (∀ t u, t ∈ toSchema ts → u ∈ toSchema ts →
          FileRefEdge f (moduleName nm t.path) (moduleName nm u.path) →
          RefEdge (toSchema ts) t.path u.path)
     ∧ (∀ t u, t ∈ toSchema ts → u ∈ toSchema ts →
          moduleName nm t.path = moduleName nm u.path → t.path = u.path)
     ∧ Rooted (toSchema ts))
  ∧ (∀ p t, (p, t) ∈ ts → ∀ k o, (k, o) ∈ t.members → ∀ τ, o.joined = some τ →
        (∀ ty, ty ∈ o.seen → ty ⊑ τ) ∧ (∀ σ, (∀ ty, ty ∈ o.seen → ty ⊑ σ) → τ ⊑ σ))
  ∧ (∀ p t, (p, t) ∈ ts → ∀ k o, (k, o) ∈ t.members →
        o.values + o.nulls + o.absent = t.visits
        ∧ (o.nullable = true ↔ o.values < t.visits))

structure_preserved

The tree the documents induce and the graph a reader finds in the generated signatures are the same graph, and it is rooted.

theorem structure_preserved (nm : Naming) (s : Schema) (f : File)
    (hgen : gen nm s = .ok f) :
    -- nothing lost
    (∀ p q, CollEdge s p q → FileCollEdge f (moduleName nm p) (moduleName nm q))
  ∧ (∀ p q, RefEdge s p q → FileRefEdge f (moduleName nm p) (moduleName nm q))
    -- nothing invented
  ∧ (∀ t u, t ∈ s → u ∈ s →
        FileCollEdge f (moduleName nm t.path) (moduleName nm u.path) →
        CollEdge s t.path u.path)
  ∧ (∀ t u, t ∈ s → u ∈ s →
        FileRefEdge f (moduleName nm t.path) (moduleName nm u.path) →
        RefEdge s t.path u.path)
    -- the same graph, not a quotient of it
  ∧ (∀ t u, t ∈ s → u ∈ s →
        moduleName nm t.path = moduleName nm u.path → t.path = u.path)
    -- and rooted
  ∧ Rooted s

Proved, but not needed for the guarantee

A further 59 results are proved in the repository and do not appear in the tree above. That is not an oversight, and in one case it is the point.

Name mangling is the interesting case. One might expect “distinct members become distinct columns” to be what makes the signature well formed. It is not how the proof goes: gen checks its own output for repeated names before returning it, and gen_wellFormed is proved by inverting that check. So well-formedness holds of every schema, including ones inference could never build, and it does not rest on mangle_injective at all. Injectivity is what makes the design sound rather than lucky — without it the generator would be relying on a runtime check to catch a collision it should never create — but the theorem above stands without it.

06

What is not proved

No goal in the repository is left open, so this section is about scope rather than about unfinished work.

  1. That inference never trips the generator's check. Correctness 3–6 hold because gen checks its input has the shape a corpus produces and refuses one that does not. That is the stronger arrangement for a reader of the output — the properties hold of every file emitted, whatever it was handed — but it does not by itself say the check never fires on a real corpus. It does not: tables are keyed by path, a repeated member is refused, and the walk records a table before descending into what it holds. Turning that sentence into a theorem is the obvious next piece.
  2. That the emitted OCaml compiles. Well-formedness constrains names, not references. A module naming a unit that is compiled after it satisfies the definition and still does not build. The generator does emit units in a topological order; nothing yet states that it is one.
  3. Anything about rows surviving. This program emits a description of tables and never emits a row, so there is no object for a preservation theorem to be about. A round trip could only ever hold up to member order, explicit null versus an absent key, and the written form of a number — all three discarded by design.
