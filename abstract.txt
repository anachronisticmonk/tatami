Tatami reads schemaless JSON and derives a columnar schema from it, along with the OCaml types that schema implies. The conversion is backed by a Lean 4 proof in five named parts. The emitted signature is well formed. The schema is canonical: shuffle the documents and the answer is equal, not merely equivalent. Structure is preserved, so the graph in the signatures is the graph the documents induce, with no edge lost or invented. Every type is principal: wide enough to admit every value that appeared in the data, and no wider. And nullability is exact: a field is optional precisely when some document lacked a value there. 221 theorems and lemmas stand behind that, and the generator emits one .mli per table plus a loader that ingests the JSON into a database.

OCaml does the rest. The loader streams documents into tables as the signature describes them, keeping each row's parent and the position it held in the array it came from. Postgres is reached through pgx, a client written in OCaml.

We ran the result across dataset sizes and query shapes: reassembling one document, counting over a single column, grouping, and joining up three levels. That gives an informed account of where a columnar layout wins and where it does not. Every run is differentially tested, so the answer from querying the raw JSON must equal the answer our store returns before any timing is believed. On the computed query the columnar store runs 3.34x against row-major.
