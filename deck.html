The problem

Nobody wrote down what shape the data is

You are handed a pile of JSON — a CI service's build history. Repos hold runs, runs hold jobs, jobs hold steps. Four levels, every level an array, no declaration anywhere.

  • Optionality has two spellings: a field may be null, or simply absent. They mean the same thing.
  • The usual answer is to guess the schema, hand-write a loader, and discover where you guessed wrong in production.
  • A wrong guess compiles cleanly — and fails at load, on real data.
The thesis

An .mli is a contract

A signature file sits on a boundary and says exactly what crosses it. That is the right home for an inferred schema — not a JSON-schema document some loader re-interprets at runtime.

Read it and you know the table:

  • its columns and their types;
  • that error is the only column that can be null;
  • that ms is int, not int option — the data never lacked it;
  • of_job — the foreign key, expressed as a function;
  • idx — the array position, kept because order is information a table would otherwise lose.
Why functional

Two languages, one discipline

The pipeline is functional end to end. That is not a costume for the hackathon — it is what makes the central claim checkable.

Lean 4 — inference and proof

The one component everything else rests on. In Lean it carries theorems, not just tests — and the thing proved is the thing that runs.

OCaml — loading, storage, measurement

The contract is enforced by the compiler that builds the loader. Stores, queries and benchmarks are all OCaml — no imperative escape hatch.

The one place correctness had to be guaranteed is the one place we could hand to a theorem prover.

The proof · sharpest part

Why nullability had to be proved

The counts identity. Every visit to a table is accounted for at every field — a value, an explicit null, or an absence. Nothing else.

And the flag reads off it. A field is optional precisely when it carried a value fewer times than its table was visited.

Absence is computed by truncating subtraction. Without the identity a field somebody omitted could report absent = 0, come out non-optional, and the generator would emit string for data needing string option.

The store does abort loudly rather than corrupt. But at load time, on production data, in code the compiler accepted. The theorem makes the condition unreachable.

The payoff

The proof is what lets us delete the mask

8 bytes an element against 24 — but size is the smaller half. The dense array is walked; the boxed one is chased, and the next address is unknown until the current pointer lands.

The measurements

Correctness before speed

Five queries, answered by three stores — raw Yojson, a row-major record store, and the columnar one. Every store implements the same signature, because a benchmark where each side answers a question shaped to suit it measures nothing.

All three agree, on every corpus. Only then are the timings worth reading.

The measurements · results

Which queries the types make faster

Not a faster database. Two go the other way by design — document is what a row store is for. The claim: once the type is known you can predict which queries get faster, from the schema, before reading a row.

The measurements · selectivity

What a planner would want to know

Sweeping the predicate threshold — qty > n — across the same 50 MB corpus.

A U-curve. Selective predicates and full scans both win; the middle is where per-row branching costs most — and the schema already says which columns are scannable.

What is new here

Columnar storage is solved. This is about the bit upstream of it.

Not claiming

Arrow, Parquet, Polars, DuckDB — decades of engineering. JSON schema inference is a studied problem. Machine-checked type inference is older still. A weekend of OCaml improves on none of it.

Claiming

All of them take the schema on faith. Arrow and Parquet require a schema and never derive one — and whether a column is nullable arrives from outside, sampled or hand-declared. That unverified bit decides whether a validity bitmap is allocated for every row, forever.

The most expensive decision in a columnar layout is the least checked one. We make it a theorem, then spend it: no mask where the proof says none can be needed.

And the part we think is genuinely new — nullability analysis is conservative: combine two maybe-null values and a sound analysis must call the result maybe-null, so masks propagate until everything is optional again. Here the leaves are generated with proved-exact nullability, so ms total and rate total makes ms × rate total — provably, not by assumption. The exactness flows downstream instead of decaying. It is why computed at 3.34× beats scan at 3.21× while doing strictly more work per row.
